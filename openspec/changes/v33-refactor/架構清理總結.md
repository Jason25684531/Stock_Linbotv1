### 2. **混亂的參數存取模式**

**發現問題**:

在專案中發現 **3 種不同的參數存取方式並存**：

```python
# 方式 1: 直接導入全域變數（已廢棄）
from tool.strategy import V30_PARAMS
max_days = V30_PARAMS['MAX_HOLD_DAYS']

# 方式 2: 從資料庫讀取（推薦）
params = get_v30_params_from_db()

max_days = Config.V30_MAX_HOLD_DAYS
```

**問題**:
- 新手開發者困惑：應該用哪一種？
- 維護成本高：修改參數需要改 3 處
- 容易出錯：不同方式返回值可能不一致

## 🎯 清理原則

### 1. **單一職責原則 (Single Responsibility Principle)**

```python
# ❌ Before: app.py 同時處理路由和業務邏輯
@app.route('/recommendation')
def recommendation():
    # 業務邏輯寫在這裡（錯誤）
    df = pd.read_sql(...)
    picks = df[df['rsi'] > 40]
    return jsonify(picks)

# ✅ After: app.py 只負責路由，邏輯在 tool/
@app.route('/recommendation')
def recommendation():
    from tool.strategy import get_v31_recommendation
    picks = get_v31_recommendation()  # 呼叫業務層
    return jsonify(picks)
```

---

### 2. **DRY 原則 (Don't Repeat Yourself)**

```python
# ❌ Before: 同一邏輯出現在多個檔案
# app.py
def calculate_v30_signal(row):
    # 30 行邏輯...

# tool/strategy.py
def calculate_v30_signal(row):
    # 相同的 30 行邏輯...

# ✅ After: 只保留一份權威實作
# tool/strategy.py
def calculate_v30_signal(row):
    # 唯一的邏輯實作...

# app.py
from tool.strategy import calculate_v30_signal  # 直接引用
```

---

### 3. **依賴倒置原則 (Dependency Inversion)**

```python
# ❌ Before: 上層直接依賴下層實作細節
from tool.strategy import V30_PARAMS  # 直接依賴全域變數
max_days = V30_PARAMS['MAX_HOLD_DAYS']

# ✅ After: 透過抽象介面存取
from tool.strategy import get_v30_params_from_db  # 依賴抽象函數
params = get_v30_params_from_db()
max_days = params['MAX_HOLD_DAYS']
```
