# Feature Specification: TWSE MCP 現代化資料流與動態互動升級

**Feature Branch**: `003-modernize-twse-dataflow`  
**Created**: 2026-04-08  
**Status**: Draft  
**Input**: User description: "建立「TWSE MCP 現代化資料流與動態互動升級」規格：拔除舊有不穩定的 HTML 爬蟲，全面改用內網 TWSE MCP Server 的標準 JSON API，並將 LINE Bot Rich Menu 與 AI 代理升級為直接對接 MCP 數據的動態互動能力。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 穩定完成每日與季度資料同步 (Priority: P1)

作為系統維運人員，我需要市場資料與財報更新流程以單一、穩定的標準資料契約運作，避免因網站版面或 HTML 結構變動導致每日更新中斷，影響後續選股、回測與報表。

**Why this priority**: 這是整個升級的核心價值。若資料同步仍依賴脆弱來源，Rich Menu 與 AI 查詢即使完成，也會建立在不可靠的資料基礎上。

**Independent Test**: 針對一個交易日與一個已公告季度執行同步，驗證市場資料摘要、籌碼資料與財報資料可從 MCP 標準 JSON 載入、正規化並寫入既有儲存契約，且下游流程可直接沿用。

**Acceptance Scenarios**:

1. **Given** MCP 可提供指定交易日的市場摘要與籌碼資料，**When** 每日更新流程執行，**Then** 系統應寫入既有市場資料欄位，且不需要修改下游查詢契約。
2. **Given** MCP 可提供指定季度的財報資料，**When** 財報更新流程執行，**Then** 系統應將資料轉為既有財務欄位語義並供既有策略與報表直接使用。
3. **Given** 上游回傳額外欄位或欄位順序變動，**When** 同步流程執行，**Then** 系統應只處理已定義欄位並忽略不落地欄位，不因格式噪音而中斷。

---

### User Story 2 - 透過 Rich Menu 即時取得動態市場資訊 (Priority: P2)

作為 LINE Bot 使用者，我希望點擊 Rich Menu 的動態按鈕後，立即收到最新的大盤摘要、籌碼趨勢或隨機策略內容，而不是固定文案或需要額外輸入指令。

**Why this priority**: 這是使用者直接可見的升級成果，能把新的 MCP 資料流轉化為更直覺的互動體驗，提升 Line Bot 的實用性。

**Independent Test**: 在 Line Bot 中點擊三個指定按鈕，驗證每個按鈕都能觸發對應行為，並以最新 MCP 資料回覆格式化文字或圖文訊息。

**Acceptance Scenarios**:

1. **Given** 使用者已開啟 LINE Bot Rich Menu，**When** 點擊大盤摘要按鈕，**Then** 系統應回傳最新市場摘要而非靜態內容。
2. **Given** 使用者已開啟 LINE Bot Rich Menu，**When** 點擊籌碼趨勢按鈕，**Then** 系統應回傳最新籌碼動向摘要並指出資料時間點。
3. **Given** 使用者已開啟 LINE Bot Rich Menu，**When** 點擊隨機策略按鈕，**Then** 系統應回傳一則可讀的策略推薦或策略說明內容。

---

### User Story 3 - AI 代理可自主查詢市場與財務資訊 (Priority: P3)

作為研究或分析人員，我希望 AI 代理能在需要時自主查詢公司基本資訊、財報與籌碼資料，讓問答結果建立在即時且標準化的資料上，而不是只依賴靜態提示或過時快取。

**Why this priority**: 這能把 MCP 能力擴展到更高價值的研究流程，讓 AI 代理在分析與說明時具備可追溯資料來源，降低錯誤解讀風險。

**Independent Test**: 針對公司診斷、財報查詢與籌碼查詢提出自然語言問題，驗證 AI 代理可觸發對應查詢能力並根據結果產生回應。

**Acceptance Scenarios**:

1. **Given** 使用者詢問某檔股票的公司概況，**When** AI 代理處理該問題，**Then** 代理應可取得最新公司基本資訊並回覆摘要。
2. **Given** 使用者詢問近期籌碼方向或財報重點，**When** AI 代理處理該問題，**Then** 代理應能查詢對應資料並在回覆中使用該資料支撐結論。

### Edge Cases

- 若 MCP 在非交易日或尚未揭露期間回傳空資料，系統必須明確區分「合法無資料」與「上游異常」，避免誤導使用者。
- 若 MCP 回傳缺少必填欄位或欄位型態不符，系統必須拒絕該筆或該批資料寫入，並保留可追蹤的錯誤原因。
- 若市場摘要、籌碼資料與財報資料僅部分成功取得，系統必須保留成功結果並清楚標示失敗部分，不得以不完整內容假裝成功。
- 若使用者短時間內重複點擊 Rich Menu 動態按鈕，系統必須回應最新可用結果，且不產生重複寫入或互相污染的狀態。
- 若 AI 代理查詢期間 MCP 暫時不可用，代理必須明確說明資料目前不可取得，而不是編造數值或推論結果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須將 MCP 標準 JSON 契約作為本功能範圍內市場摘要、公司基本資訊、籌碼資料與財報資料的唯一正式外部資料來源。
- **FR-002**: 系統必須移除本功能範圍內對公開 HTML 頁面解析的正式依賴，避免網站版型變動影響資料同步。
- **FR-003**: 系統必須將 MCP 回傳資料正規化為既有儲存契約，使既有資料表、報表、策略與回測流程可在不改寫查詢契約的前提下繼續運作。
- **FR-004**: 系統必須明確定義市場資料、籌碼資料與財報資料的必填欄位、可選欄位與不落地欄位，並對缺漏或不相容欄位提供可追蹤的拒絕理由。
- **FR-005**: 同一交易日或同一季度的重複同步必須維持冪等結果，只能更新相同業務鍵對應的資料，不得新增重複紀錄或破壞其他日期資料。
- **FR-006**: 當單一資料模組失敗時，系統必須保留其他模組的成功結果與既有有效資料，並將整體執行狀態標記為部分成功或可重試失敗。
- **FR-007**: 系統必須為外部資料互動提供一致的錯誤處理與操作診斷，使維運人員能識別失敗模組、目標日期或期間，以及失敗原因。
- **FR-008**: LINE Bot Rich Menu 必須提供三個動態互動入口，分別對應大盤摘要、籌碼趨勢與隨機策略，且每個入口都需以結構化事件觸發對應行為。
- **FR-009**: 當使用者觸發 Rich Menu 動態入口時，系統必須直接使用最新可用的 MCP 資料回覆格式化文字或圖文訊息，而非預先寫死的靜態回覆。
- **FR-010**: Rich Menu 的每個動態入口都必須回傳可被一般使用者直接理解的內容，至少包含主題摘要與資料時間點。
- **FR-011**: 若動態入口查詢失敗，系統必須回覆清楚、可行動的失敗訊息，說明稍後重試或目前資料不可用，而不是無回應或回傳空白內容。
- **FR-012**: AI 代理必須具備可呼叫的市場與財務查詢能力，至少涵蓋公司基本資訊、財報資料與籌碼資料三類查詢。
- **FR-013**: AI 代理在使用外部資料回答問題時，必須以查詢結果為基礎生成回覆，並在資料不足或查詢失敗時明確揭露限制。
- **FR-014**: 系統必須讓新資料流與互動能力遵守明確的輸入與輸出契約，以支援測試、維護與跨模組整合。
- **FR-015**: 任何因本功能導致的使用方式、資料意義或操作流程變更，都必須同步反映在對應文件與操作說明中。

### Key Entities *(include if feature involves data)*

- **MCP Market Snapshot**: 表示特定交易日的大盤摘要、公司基本資訊或籌碼資料批次，關鍵屬性包含資料日期、資料類別、記錄集合與資料來源狀態。
- **Financial Statement Batch**: 表示特定年度與季度的財報資料批次，關鍵屬性包含公司代號、期間、主要財務數值、衍生指標與資料有效性狀態。
- **Dynamic Menu Action**: 表示 Rich Menu 中一個可觸發的互動入口，關鍵屬性包含動作識別碼、使用者觸發時間、對應資料主題與回應格式。
- **Bot Response Payload**: 表示 LINE Bot 對動態入口的回覆內容，關鍵屬性包含主題摘要、資料時間點、訊息型態與失敗時的替代說明。
- **Agent Query Capability**: 表示 AI 代理可呼叫的一項結構化資料查詢能力，關鍵屬性包含查詢意圖、可接受參數、查詢結果與失敗說明。
- **Sync Execution Result**: 表示一次資料同步或即時查詢的執行結果，關鍵屬性包含目標資料範圍、處理狀態、成功與失敗摘要、耗時與重試資訊。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常交易日條件下，95% 的市場資料與籌碼同步執行可於 2 分鐘內完成，且結果可被既有下游流程直接使用。
- **SC-002**: 在正常上游條件下，95% 的單一季度財報更新可於 1 分鐘內完成，且重複執行不會產生重複紀錄。
- **SC-003**: 驗收測試中，100% 的 Rich Menu 動態按鈕點擊都能在 5 秒內回覆對應主題內容或明確失敗訊息。
- **SC-004**: 驗收測試中，100% 的 AI 代理市場/財務查詢案例都能取得資料支撐的回答，或在資料不可用時明確揭露限制，不出現編造數值。
- **SC-005**: 上線後一個月內，因上游 HTML 結構變動造成的資料同步中斷事件應降低 90% 以上。
- **SC-006**: 驗收測試中，所有既有依賴市場資料與財報資料的主要流程在不改變查詢契約的前提下通過既有功能驗證。

## Assumptions

- 內網 TWSE MCP Server 會持續提供穩定可用的標準 JSON 契約，並可覆蓋本功能所需的大盤、公司、籌碼與財報主題。
- 本功能以維持既有資料儲存語義與下游相容性為前提，不新建額外的使用者可見資料模型來取代現有主流程。
- Rich Menu 的此次升級範圍僅限三個指定動態入口，不包含整體版面重設或新增更多操作區塊。
- AI 代理的此次升級目標是新增可控的資料查詢能力，不包含重新定義整體提示策略或建立新的多代理架構。
- 月營收、新聞摘要與其他非本次指定主題的資料來源整合不在此次規格範圍內，除非它們是維持現有相容性所必需的既有依賴。
